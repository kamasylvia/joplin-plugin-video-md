# Submission Notes

Status: **prepared, not submitted.** The repository is public; publishing to
the Joplin registry is a separate submission step.

## Pre-flight checklist

- [x] Repository is public.
- [x] `LICENSE` (MIT) is present.
- [ ] `npm ci && npm test && npm run dist` passes from a clean checkout.
- [ ] `publish/` contains exactly one `.jpl` and one `.json`.
- [ ] `git status --porcelain` is empty and `HEAD` is pushed.
- [ ] `src/manifest.json` version equals `package.json` version.
- [ ] The `.jpl` has been installed in Joplin and a real note has been verified.
- [ ] README reflects the current behavior.

## Submission flow

Joplin's plugin pipeline is repository-based: it scans the repository at a
specific commit, reviews the report, then builds and publishes from source.

1. Repository is public (visibility is independent of registry publication).
2. Push a clean commit.
3. Verify locally:

   ```bash
   npm ci
   npm test
   npm run dist
   git status --porcelain
   git rev-parse HEAD
   ```

4. Create the submission issue. The current `generator-joplin` targets
   `joplin/plugins-test`; confirm the live target in the official docs before
   submitting.

   Title:

   ```text
   [Plugin Submission] joplin-plugin-video-md v1.0.0
   ```

   Body:

   ```json
   {
     "plugin_name": "joplin-plugin-video-md",
     "version": "1.0.0",
     "repository_url": "https://github.com/kamasylvia/joplin-plugin-video-md",
     "commit_hash": "<full 40-character HEAD>"
   }
   ```

5. Wait for the CodeQL scan report and fix any findings.
6. After maintainer approval, the publish workflow runs `npm ci` and
   `npm run dist`, then publishes the artifacts.

The scan requires `src/manifest.json`. Do not move the manifest back to
`dist/`; `dist/` is generated by the build.

## Releases and updates

- Bump `version` in both `src/manifest.json` and `package.json`.
- Rebuild, commit, and push.
- Submit the same plugin ID and repository URL with the new version; it must be
  greater than the currently published version.
- Do not change `id` or `repository_url`; ownership is tied to them.

No npm publish is required for the repository-based flow.
